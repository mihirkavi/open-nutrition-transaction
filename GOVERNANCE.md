# OpenNutri Governance

OpenNutri begins as a maintainer-led open project with a documented path toward
independent, multi-stakeholder stewardship. Decisions must favor interoperability,
privacy, implementability, and ecosystem neutrality over any single product.

## Roles

- **Contributors** propose issues, examples, fixes, and OpenNutri Improvement Proposals (ONIPs).
- **Editors** check technical clarity, compatibility, test evidence, and documented tradeoffs.
- **Maintainers** merge changes, publish releases, address security issues, and record decisions.

## Decision process

Normative changes require an ONIP, public review, conformance examples, and tests.
Editors seek rough consensus and document objections. Maintainers may reject a
proposal that weakens consent, data minimization, provenance, neutrality, or
backward compatibility. Security fixes may follow an embargoed process before a
public record is published.

No participant receives preferential protocol access. Governance should add
representatives from consumers, food providers, applications, nutrition
professionals, privacy/security experts, and standards communities as adoption grows.

## Releases

Software uses semantic versioning. The standard uses explicit major/minor
versions. Breaking changes require a new major schema namespace and migration
guide. Deprecated features remain documented for at least one supported major version.
